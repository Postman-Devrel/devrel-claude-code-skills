The details:

  • Context Graph: a live index of services, endpoints, schemas, consumers, owners, and runtime call relationships.

🔁 From API change to CI in plain-English prompts

The Rundown: Updating the code is the easy part of changing an API. This post hands the rest to Claude, from the changed endpoint to a CI run on every push, all from the terminal.

The details:

  • The chain: API change, Context Graph finds what needs updating, collection syncs, lint checks the schema.
  • Stand-in: a mock covers what isn't live yet and confirms the tests work.
  • Locked in: CI runs the tests on every push.
  • No ticket trail: it all runs as one connected task, not a separate ticket per step.

Why it matters: Without it you get a collection that looks right but isn't, and the next person trusts it anyway.
